# Локальная сборка

Команда `./build.sh conf` собирает все профили в `conf/`.

Генераторы профилей находятся в `source/build-scripts/sr_*.sh` и используют общий шаблон `source/General.txt`.
Они запускаются последовательно, поскольку используют общий временный файл.

### Особенности проекта

#1<br>
Для профиля `sr_ru_mini.conf` скрипт скачивает `source/community.list` из ветки `main` исходного репозитория.

#2<br>
Следующие файлы не перезаписываются скриптами сборки:

- `rules/domains_discord.list`
- `rules/domains_youtube.list`
- `rules/voice_ports.list`

### Issues

#### #1 обработать сбой загрузки в mini

В `source/build-scripts/sr_ru_mini.sh` результат `curl -s` передаётся в `awk`.
Когда тестовый `curl` завершился с кодом 6, команда `./build.sh conf` вернула 0.
В таком профиле отсутствуют правила из community.list, и трафик, который должен был совпасть с ними, может попасть под `FINAL,DIRECT`.
Workflow может опубликовать этот результат.
Поведение унаследовано от прежней сборки.

Сохранить указанный в CONTRIBUTING.md источник, загружать список с `curl -fsSL` во временный файл и проверять успешность загрузки и наличие доменов до перезаписи готового профиля.
Проверка исправления — при сбое DNS, HTTP 404 или пустом ответе сборка должна вернуть ошибку и сохранить предыдущий mini-профиль.

#### #2 Изолировать одновременные локальные сборки

Все генераторы используют `conf/General.tmp`.
Последовательный вызов в `build.sh` защищает только один процесс.
При двух запусках в одном каталоге один процесс может заменить шаблон или удалить его во время работы другого.
Это замечание основано на чтении кода.
Предложение — собирать профили в отдельном временном каталоге каждого запуска и переносить готовые файлы в `conf/` после успешной генерации.
