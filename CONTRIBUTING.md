# Локальная сборка conf/

Команда `./build-shadowrocket-conf.sh` собирает все профили в `conf/`.

Генераторы профилей находятся в `source/build-scripts/sr_*.sh` и используют общий шаблон `source/General.txt`.<br>
Они запускаются последовательно, поскольку используют общий временный файл.

### Особенности проекта

#1<br>
Для профиля `sr_ru_mini.conf` скрипт скачивает `source/community.list` из ветки `main` исходного репозитория.

#2<br>
Следующие файлы не перезаписываются скриптами сборки:

- `rules/domains_discord.list`
- `rules/domains_youtube.list`
- `rules/voice_ports.list`

### Issues & Audit

#### #1 Обработать сбой загрузки в mini

В `source/build-scripts/sr_ru_mini.sh` результат `curl -s` передаётся в `awk`.<br>
Если тестовый `curl` падает в ошибку, команда `./build-shadowrocket-conf.sh` вернет 0.<br>
В таком профиле отсутствуют правила из community.list, и трафик, который должен был совпасть с ними, может попасть под `FINAL,DIRECT`.<br>
Workflow может опубликовать этот результат.

Поведение унаследовано от прежней сборки.

#### #2 Изолировать одновременные локальные сборки

Все генераторы используют `conf/General.tmp`.<br>
Последовательный вызов в `build-shadowrocket-conf.sh` защищает только один процесс.<br>
При двух запусках в одном каталоге один процесс может заменить шаблон или удалить его во время работы другого.<br>

Желательно собирать профили в отдельном временном каталоге каждого запуска и переносить готовые файлы в `conf/` после успешной генерации.
